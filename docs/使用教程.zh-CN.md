# AI 短剧连续性制作使用教程

这套 skill 帮助你在逐段生成短剧时，把已经采用的成片作为下一段的事实起点。你负责决定哪一版采用，助手负责核对衔接、修改后续提示词，并维护完整剧本文档和本地上传文件夹。

## 1 准备项目

准备完整剧本、人物和场景参照图，以及当前正在使用的提示词文件。已有项目沿用原目录；不要为了调用 skill 另复制一套成片和图库。

建议的项目组织如下，已有文件名不同也可以保持原结构：

```text
示例项目/
  项目连续性记录.md
  完整剧本文档/
    示例剧 完整剧本与逐段提示词.docx
  参照图库/
  采用成片记录/
  逐段提示词/
  按镜头上传/
    第02集/
      第03段 E02-03/
        本镜头完整提示词.txt
        上传说明.txt
        首帧.png
        本段需要的独立参照图.png
```

路径示例仅用于说明，请替换为自己的项目路径。项目材料放在自己的项目目录，不要放进公共 skill 仓库。

## 2 安装并确认调用

按 [README 的安装步骤](../README.md#安装) 安装 `skills/ai-drama-continuity`。这是一套说明型技能，无需为它单独注册视频平台账号或填写 API 密钥。

在 Codex 提示中使用 `$ai-drama-continuity`；支持技能选择器的界面也可通过选择器调用。如果选择器未显示该技能，检查安装目录和 `SKILL.md` 是否位于技能文件夹第一层，避免多套一层同名文件夹。

宿主的发现和调用方式可能不同，参考 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。如果当前界面不支持安装技能，也可以把技能文件作为工作说明提供给能够读取文件的助手，但访问视频和更新本地文件仍取决于该环境的工具能力。

## 3 建立第一次项目记录

第一次使用时，把项目路径和你已确定的制作要求告诉助手：

```text
使用 $ai-drama-continuity。
项目目录：D:/AI-Drama/示例项目。
已有完整剧本和人物场景参照图，请先读取并沿用。
制作设置：9:16竖屏，单段最多15秒，每段最多9张图片，首帧计入。
同集接上一段尾帧，跨集独立开场。
声音由视频模型生成，不加对白字幕。
建立项目连续性记录，整理逐段提示词与按镜头上传文件夹。
交付完整剧本 DOCX，保存到原项目。
```

以上设置只是示例。如果你使用横屏、10秒上限或不同图片数量，直接写实际要求。已有设置不会因为技能的示例而改变。

助手应记录固定空间方向、人物服装、道具主人和位置、生成参数，以及已采用到哪一段。项目记录的模板在 [project-record.md](../skills/ai-drama-continuity/references/project-record.md)。

## 4 生成一段后确认采用

先在视频生成平台完成一段，确认希望保留的版本，然后发送段号、采用声明和视频：

```text
使用 $ai-drama-continuity。
第02集第02段，这版采用。
成片路径：D:/AI-Drama/示例项目/成片/E02-02.mp4。
尾帧路径：D:/AI-Drama/示例项目/按镜头上传/第02集/第03段 E02-03/首帧.png。
请核对成片与尾帧，调整下一段及确实受影响的后续提示词。
已完成内容不改，直接同步本地上传文件夹。
主交付为包含本次修订的完整剧本 DOCX。
```

也可以直接附上视频和尾帧。只问“这段效果怎么样”表示评估，不等于采用；你尚未选定时，应先让助手检查并给建议。

“采用”锁定的是你交付的版本。重复人影、家具穿模等仍需记录为生成异常，不自动变成新的剧情设定。

## 5 看助手是否完成真实核对

核对结果应说明实际看了哪些画面、能否听音频，以及尾部的可见状态。重点查看以下几项：

| 项目 | 应说明的内容 |
| --- | --- |
| 人物 | 人数、位置、高度、姿态、朝向，画外人物的留存 |
| 手与物件 | 左右手持物、是否拿放或换手、道具数量 |
| 手机 | 屏幕或后盖朝向、当前可见界面、手电状态 |
| 空间 | 门的开闭、床桌位置、通路、异常结构 |
| 灯光 | 实际亮度、冷暖光源、是否发生开关灯动作 |
| 尾帧 | 真正最后解码帧的提取依据，与所用高清图是否对应 |

未知项应写“未知”或“画外”。例如结尾只看到纸和一只手，不能声称末帧同时看到了另外两个人和手机；可用此前最近可见状态维护画外连续性。

不能试听音频时，不能把抽帧检查说成声音或口型验收。文件名里的结束时间也不一定是图像帧的时间戳。

## 6 使用下一段上传文件夹

打开下一段对应的本地文件夹，先读 `上传说明.txt`，核对实际图片数和每张用途。将现有首帧设为平台的首帧，其余图片作为人物、场景、道具或文字参照。

```text
图片上限 = 专用首帧 + 本段所有独立参照图
```

TXT 和 DOCX 不计作参照图片，也不用当作图片上传。不能把同一镜头的多张候选尾帧全部选择为首帧。

如果说明显示“首帧已放入”，直接使用该图。图片没改时，无需重新下载或复制；提示词可能已更新，所以仍要读取最新的 `本镜头完整提示词.txt`。

把该 TXT 的完整正文提交给视频模型。不要只复制对白，也不要让模型凭“按前文”推断未写明的状态。

## 7 收取完整 DOCX

默认主交付应是完整 DOCX，包含项目全部既定剧本和逐段完整提示词，并纳入本次修改。仅下一段 TXT 或变更说明不能代替完整文档。

助手应在原项目另存新版本，保留旧版；已完成内容不覆盖。检查完整 DOCX、逐段 TXT、汇总和上传文件夹中的正文是否一致。助手还应说明文档的排版检查情况及实际限制。

如果只是问建议、不希望修改文件，可明确说：

```text
只核对并给建议，先不改本地文件，不生成新的 DOCX。
```

## 8 下一轮继续

下一段生成并采用后，继续发送“段号＋这版采用＋视频”，附上尾帧或可访问路径。新成片可能没有执行旧提示词里的全部动作，每一轮都需要从实际画面重新核对。

如果接受的成片中含有错误，可以指定保留范围：

```text
第02集第03段，这版采用。保留成片中的家具异常，不改已完成内容。
请记录异常，下一段接实际尾帧后明确硬切到可靠近景，保持原剧情。
完整 DOCX 和本地上传文件夹同步更新。
```

如果需要横屏或改变段长，可明确从哪一段生效。不要让助手回改此前已经锁定的成片。

## 常见问题

**会自动生成视频吗？**

不会。这套 skill 编写提示词和维护衔接资料，视频由你在所用平台生成。它不附带视频 API、自动付费或自动发布功能。

**我必须用15秒、竖屏、9张图吗？**

不必。这些只是可覆盖的示例，实际限制以所用模型和项目设置为准。

**没有尾帧怎么办？**

提供采用视频，让助手在能够解码的环境中提取真正最后一帧。无法提取时，应明确缺失，不用片头或随便一张截图顶替。如果结尾是黑场或穿模，先说明问题，再按明确安排承接或选择截点。

**本地路径无法访问怎么办？**

先给当前助手授权访问项目，或提供可读取的素材。未成功写入本地时，助手不能声称“已同步”；在云端环境中，本地绝对路径通常不能直接访问。

**能确保人物永远不穿模吗？**

不能。明确动作顺序、持物和机位有助于减少歧义，视频模型仍可能出错，需要逐轮核对。

**我需要公开自己的项目才能用吗？**

不需要。公共仓库是通用工作流程，你自己的完整剧本、素材、采用记录和账号配置留在自己的项目与执行环境。详见 [隐私与发布范围](隐私与发布范围.md)。
